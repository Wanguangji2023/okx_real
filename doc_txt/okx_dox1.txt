建议：

# 引入"回本价"概念：考虑双边手续费
FEE_RATE = float(os.getenv("TAKER_FEE_RATE", "0.001"))  # 默认 0.1%
def _breakeven_price(self):
    """考虑买卖双边手续费的保本价"""
    return self.position_price * (1 + 2 * FEE_RATE)
在 price >= self._breakeven_price() 时才判定为"回本"。
复核：_breakeven_price() 已实现且口径比文档更准（成本额÷实际到账量÷(1-费率)，

十、本轮新发现（文档未列出，优先级高于 9.2/9.3 各条）

10.1 [P0·已修复] 卖出前按平台可用量改写持仓，会把单位成本拍平、低估保本价
_execute_sell 中 `position_amount = position_price * avail`：position_price 是买入成交均价 avgPx
（扣币之前的单位价），而 position_amount 本是买入实付金额（对应扣费前的成交量）。
两者相乘得到的是"名义成本"，丢掉了买入手续费折算进单位成本的部分，
使 _breakeven_price()=amount/qty/(1-fee) 退化为 avgPx/(1-fee)，比真实保本价低约 0.1%，
9.1.1 想防的"亏本当回本清仓"在偏离分支里又回来了。
修复：按数量比例等比缩放 amount（new_amount = old_amount × avail/old_qty），保留单位成本。

10.2 [P0·已修复·需确认] 系统参数表是中文键名，load_config 只认英文键 → 全部静默失效
配置表"系统参数"实际内容：总资金=1000000 / 单次买入比例=0.02 / 静默期=7 / 止盈触发阈值=0.05 …
而 load_config 匹配 total_funds/buy_ratio/cooldown_days/... 这些英文键，一个都对不上，
所以 buy_ratio 恒取代码默认 0.01：用户配的 2% 只跑了 1%（实测 RVN 买入 1037 USDT = 余额×1%）。
修复：加入中英文键名映射；同时把"表里有、代码里没有实际用途"的死参数在启动日志里点名，避免再被误认为生效。
需确认：映射生效后单笔下注会翻倍（≈1037 → ≈2074 USDT），是否按配置 0.02 执行？
        （可用 .env 里 BUY_RATIO 显式覆盖，或把表里改回 0.01）

10.3 [P0·已修复] 启动时 OKX 连不上就 sys.exit(1) → 持仓彻底失管（本次中断的真实原因）
15:55:24 加载配置成功，15:55:35 "OKX 账户连接失败: ssl handshake timed out" 直接退出；
本地账本里的 RVN-USDT 持仓从此无人盯守，止盈/止损全部失效。远程网络抖动每次都可能是这样。
修复：账户初始化改为指数退避重试；重试耗尽后若本地有持仓，则不再退出，
      继续起行情线程（卖出监听保住）+ 后台线程恢复账户；无持仓才退出。

10.4 [P1·已修复] 买入队列入内存副本长期陈旧，事件写盘会互相覆盖
每个 SymbolState 各自 load_buy_queue() 拿一份独立副本，之后只改自己那一行却整文件覆盖写回，
会把别的币对后来改过的状态（静默期_排除/待买入/剔除）打回旧值。
修复：所有队列变更改为"读最新→改本行→原子写"，消除陈旧副本覆盖。

10.5 [P2·已修复] _can_sell 的不可达分支（文档 9.1.3 的正解）
文档方向不对但直觉有用：把 require_profit 换成显式"最小盈利阈值"参数并取消 price=None 回退，
让唯一调用点必须显式给价，读代码时不必再推断耦合。行为不变。

10.6 [P1·已修复] 启动与运行期 IO/IO 抖动：64 币对约 800 次全文件读 + 128 次 fsync
SymbolState.__init__/add_state 对 blacklist/positions/pair_status/out_of_range(xlsx, openpyxl 全量解析)
反复整表读；越界判定每个币对都重新 load_workbook 一次。落盘侧 _save_state 每币对每 5 秒
各写一遍全表（positions+pair_status 各一次 read/rewrite/fsync），1 核机器上是最主要的 CPU/IO 开销。
修复：CSV/xlsx 读缓存（写后精确失效）、状态落盘全局闸门（最多 5s 一次，高负载放宽到 30s）、
      high_low 新高低频写合并、行情/交易文件读缓存。

10.7 [P1·已修复] 无心跳可观测 + 推送无界队列
远程中断后无法判断"最后一次活着是什么时候"；NOTIFY_POOL 队列无界，推送端点卡住时任务堆积涨内存
（本机可用内存仅约 148MB）。
修复：主循环每秒采样 loadavg/RSS，落 heartbeat JSON；推送队列设上限，超限丢弃并记日志（不阻塞行情）。

10.8 [P1·已修复] WS 握手把响应头之后的字节丢了 + 未处理分片帧
_ws_handshake 读到 \r\n\r\n 即止，同一 TCP 段里紧随的首个业务帧被丢弃（订阅回执/首笔成交可能丢）；
recv_ws_frame 忽略 FIN 位，若 OKX 下发分片消息会被当坏消息静默丢掉。
修复：残留字节回填接收缓冲；分片帧续接后再解析。
